## 2024-07-04 - Timing Attack and Plaintext PIN Logging in Auth Endpoints
**Vulnerability:** The `user_login` and `admin_login` endpoints in `app.py` were vulnerable to timing attacks due to the use of a simple string inequality comparison (`!=`) for authenticating PINs. Additionally, failed login attempts explicitly logged the user-provided sensitive PIN in plaintext, which leads to sensitive data exposure in server logs.
**Learning:** Security-sensitive string comparisons (like PINs, tokens, and passwords) should never be done with standard operators (`==` or `!=`) because they terminate early on a mismatch, allowing an attacker to deduce the target string byte-by-byte by measuring the response time. Furthermore, user-supplied sensitive data must never be included in system logs to prevent leakage to unauthorized staff or external log aggregation services.
**Prevention:** Always use `hmac.compare_digest` for validating authentication credentials and secrets to ensure constant-time comparison, neutralizing timing side-channels. Rigorously scrub log statements to ensure passwords, API keys, PINs, and other confidential data are never recorded, logging only the occurrence of an event and non-sensitive metadata (e.g., username or IP).
